# 双盘叙述一致性比较

八字与紫微共享同一出生输入，并通常由同一模型在同一会话中解释。两者不是独立测量；一致只能说明两套传统叙述在当前文本中相容，不能证明预测正确、提高科学可信度或验证出生时辰。

## 八个比较维度

| 维度 | 八字文本依据 | 紫微文本依据 |
|---|---|---|
| 立身之本 | 主线格局与用神取法 | 命宫主星组合及官禄、财帛宫 |
| 离乡/守乡 | 年月结构、驿马等辅助符号 | 身宫与迁移宫 |
| 性格 | 日主、透干十神与结构 | 命宫与福德宫 |
| 求财方式 | 财星状态与位置 | 财帛宫与生年四化 |
| 婚姻 | 配偶星与日支 | 夫妻宫及其对宫 |
| 中年节奏 | 已计算的大运 | 已计算的大限 |
| 健康短板 | 仅传统五行象征 | 仅疾厄宫传统象征 |
| 贵人主题 | 印星与低权重辅助符号 | 魁钺左右昌曲等 |

## 操作步骤

1. 先分别完成用户明确要求的两套解读。不要为了制造一致性回改前文。
2. 每个维度分别引用排盘 JSON 中的八字字段、紫微宫位和星曜。
3. 标注 `✅叙述一致`、`⚠️部分一致` 或 `❌叙述冲突`。
4. 一致时说明共同主题及各自依据，不使用“互相证明”“可信度倍增”。
5. 冲突时保留两种说法，检查输入与口径是否一致；不得通过改写词义硬凑。
6. 出生时辰有疑问时，只能建议比较相邻时辰的**盘面差异**，不能根据主观吻合度宣布某一时辰已被验证。

## 输出结构

1. 八维度叙述一致性表。
2. 已计算的大运/大限时间轴；没有年度计算数据时标记 `NOT_COMPUTED`。
3. 一段边界说明：这是传统体系的文本对照，不是统计验证或科学预测。

生成海报时必须使用 [report-schema.md](report-schema.md)，并通过 `scripts/validate_analysis.py`。
