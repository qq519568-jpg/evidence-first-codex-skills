# 开工自检卡（执行端 v4）

## -1. 商业与模式

- [ ] 已选择`EXPLORE`或`PRODUCTION`；未发布、练手和工具验证默认`EXPLORE`
- [ ] 本轮会产生`CONTENT_PROGRESS`或`CAPABILITY_PROGRESS`
- [ ] 导演两分钟能完成的GUI操作已直接交给导演
- [ ] 同类任务若预计重复三次，已比较实时桥接、脚本、成熟软件/API和人工
- [ ] 15—20分钟无新可见成果或同类问题第二次出现时执行`PIPELINE_STOP`

## 0. 来源与授权

- [ ] 已读冻结的 `SOURCE_TRUTH_vN`，Shot ID/时间码/证据帧齐全
- [ ] 已区分可见事实、解释、未知和禁止发明内容
- [ ] 复刻/改编模式、输出画幅、FPS、分辨率已由导演锁定

## 1. 语义与资产

- [ ] 一句话能写清谁/用什么/对谁/动作/结果
- [ ] 主要角色使用绑定资产，不是 bpy 方块拼人
- [ ] 镜头精度等级 L1/L2/L3 已选；L0 仅技术占位并挂 ticket
- [ ] 每角色至少三项身份线索稳定
- [ ] 武器类型、握点、朝向和归属可辨
- [ ] 准备/接触/结果三帧和接触点已定义

## 2. YAML 与场景

- [ ] 十项输入闸门全过
- [ ] 相机首尾、焦段/视场、注视、关键帧、切点齐全
- [ ] 影响走位、遮挡和接触的场景几何齐全
- [ ] `Unknowns` 未被脑补进动作
- [ ] 写 bpy 前已读 `执行端Blender5.2实战坑.md`
- [ ] 探索期优先使用已验证的实时Blender桥接；导演负责打开、播放和快速摆位，AI负责批量传播与检查
- [ ] 生产编辑层无逐帧bake；世界位移使用稀疏轨迹控制，身体Action与世界轨迹分层
- [ ] 导演单帧定位已传播到前后责任区间，不存在下一帧回旧位置

## 3. 渲染前后技术 QA

- [ ] 画幅/FPS/帧数 assert
- [ ] 入画、穿模、浮空、朝向、握持、遮挡检查
- [ ] 首尾帧与 MP4 一致
- [ ] 审片版与送模版几何/动画一致
- [ ] 自动 QA 报告明确标注“仅技术健康，不代表内容正确”
- [ ] 全责任区间逐帧检查位移、速度、加速度、无因果方向反转、静止保持和落地后漂移；三帧抽查不得代替连续QA

## 4. 人工语义 QA（必须先于投下游）

- [ ] 无文字盲看：导演能准确复述镜头
- [ ] 黑色剪影：身份、武器、方向、受力仍可辨
- [ ] 三连帧：准备/接触/结果因果成立
- [ ] 来源对照：无新增剧情、角色、武器或错误结果
- [ ] 首帧同构：精修首帧与白膜首帧叠加通过

## 5. 下游能力与最小试片

- [ ] 当前界面/档位/时长/画幅/输入槽已重新确认
- [ ] 每项控制能力有 A/B/C 证据等级；C 级未进入生产协议
- [ ] 未见专用入口的 Depth/Normal/ColorMask/光流没有被假定有效
- [ ] 本轮只有一个主控制信号，辅助素材不与首帧/白膜冲突
- [ ] 先完成 2-4 秒单动作试片，再扩大
- [ ] 精确顿帧/变速/切点已安排在后期，不靠生成模型承诺

## 停止

来源冲突、白膜盲看失败、同类导演问题第二次出现、15—20分钟无新可见成果、下游能力不明或即将付费但未授权时，立即停止并比较：导演手动、实时桥接/脚本、成熟软件/API、熟练人工。探索耗材损失本身不构成停机理由。
