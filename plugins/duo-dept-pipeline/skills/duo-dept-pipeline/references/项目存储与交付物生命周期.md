# 项目存储与交付物生命周期

## 目标

把导演可见交付、项目证据、Blender生产文件和跨项目资产分开。目录名称可以适配团队环境，但职责不能混用。

## 路径必须来自项目配置

开始前从当前项目交接或用户输入确认：

- `CollectionRoot`：人类可读的项目总档案根；
- `BlenderRoot`：Blender生产工程根；
- `AssetLibraryRoot`：可选的跨项目共享资产根；
- `InboxRoot`：可选的外部生成结果临时收件箱；
- Blender与其他工具的实际可执行文件路径。

不得把维护者的盘符、用户名、桌面、下载目录或聊天工作区写成公共默认值。路径不存在时先报告并确认；`PRODUCTION`不得临时猜测正式根。

## 推荐项目结构

```text
<CollectionRoot>/<ProjectName>/
|-- 00_交付物_当前/
`-- 01_项目总档案/
    |-- 00_上下文/
    |-- 01_立项与交接/
    |-- 02_视觉真值与参考/
    |-- 03_下游投喂记录/
    |-- 04_下游回传与成片/
    |-- 05_验收与报告/
    |-- 90_历史交付物/
    `-- 99_其他/

<BlenderRoot>/<ProjectName>/
```

初始化命令要求显式提供两个根目录：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/init_project_storage.ps1 `
  -ProjectName "<ProjectName>" `
  -CollectionRoot "<CollectionRoot>" `
  -BlenderRoot "<BlenderRoot>"
```

## 内容边界

- `00_交付物_当前`：导演此刻需要打开或审看的少量文件；不是完整工作区。
- `01_项目总档案`：来源、决策、投喂、回传、验收和正式交付证据。
- `BlenderRoot`：`.blend`、缓存、渲染中间件、技术检查图和执行端脚本。
- `AssetLibraryRoot`：已核验许可、可跨项目复用的资产；不得放具体项目交付物。
- `InboxRoot`：临时收件箱；确认项目和文件身份后迁入项目档案，不能长期堆放。

## `EXPLORE` 与 `PRODUCTION`

`EXPLORE`只维护一个滚动`WORKING`结果，失败耗材可直接覆盖或放弃。不要为了试验建立复杂版本链。

进入`PRODUCTION`后才要求：

1. 正式根已由用户确认；
2. 来源、许可与语义锁状态可追踪；
3. Blender生产文件与导演交付分开；
4. 晋升版本保留可恢复的上一正式版本；
5. 项目交付记录能指向实际生产文件和验收状态。

只有导演需要查看时，才把必要的`.blend`或渲染临时复制到`00_交付物_当前`。审看结束后仍以`BlenderRoot`中的生产文件为技术权威。
