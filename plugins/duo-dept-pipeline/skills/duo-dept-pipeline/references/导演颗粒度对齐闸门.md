# 导演颗粒度对齐闸门

## 目的

在来源真值初读之后、资产需求和Scene YAML之前，对齐导演与视觉上游对“谁、在哪里、朝哪、如何运动、谁遮挡谁、谁与谁连续”的现实颗粒度。它不是附加说明，而是高难复刻镜头的生产闸门。

## 触发条件

满足任一项即强制执行：同镜三名以上人物或人物局部；强遮挡；单目来源且无可靠俯视图；相机与角色同时运动；阵营、接触、身份连续性存在歧义；导演与执行端对背景角色的数量或职责理解不一致。

## 必交付

1. 证据帧实体编号。
2. 角色/实体卡与至少三项身份线索。
3. 跨帧连续性矩阵。
4. 相对空间、地面接触和遮挡图。
5. 角色屏幕动线、世界动线与相机动线。
6. 导演裁决与仍为Unknown的项目。

没有尺度和俯视证据时，只允许屏幕左右、纵深带、遮挡边和不确定范围；禁止伪造米制俯视图。

## 编号规范

- 同阵营连续角色使用稳定编号，例如A01–A04。
- 敌方使用X01、X02。
- 武器/道具局部使用P01，避免把斧柄、旗杆或悬挂物误判成人物。
- 尚不能跨帧对应的局部实体使用`E{frame}-{letter}`，导演确认后再映射至稳定编号。
- 旧临时编号发生冲突时必须重编号，不允许同一ID同时指队友和敌方。

## 三层对齐

### 第一层：导演 ↔ 视觉上游

这是最大风险层。通过来源帧标注、角色卡、空间图和动线图建立共同现实颗粒度。未签字不得进入资产锁定和Blender语义制作。

### 第二层：视觉上游 ↔ Blender执行端/DeepSeek

这是执行合同层，原则上歧义最少。执行端只接收已冻结ID、关键帧、接触、相机轨道和禁项；不得自行解释阵营或补角色。每个Blender对象必须回指角色ID或Proxy ID，并输出可见进度、当前Shot、当前帧和阻塞原因。

### 第三层：提示词工程 ↔ 视频AI

这是模型行为校准层。不同视频AI对身份、运镜、负面约束、参考图和时间连续性的服从方式不同，不能假定提示词字面等于执行结果。每个模型必须建立行为档案：

- 身份保持倾向。
- 动作字面服从与自动戏剧化倾向。
- 运镜指令服从。
- 负面约束敏感度。
- 参考图对构图、人物和风格的偏置。
- 时序稳定性和常见幻觉。
- 建议句式、禁用句式和单轮主控制信号。

先用2–4秒最小试片做A/B测试；每轮只改变一个主要信号。未经导演确认，不进入付费生成。

## 放行条件

- 导演可用稳定ID复述镜头。
- 每个主要角色在关键帧有可见、遮挡、画外或Unknown状态。
- 相机动线与人物动线分开。
- 道具归属和握持明确。
- 敌我关系和攻击目标明确，或明确保持Unknown。
- 下游YAML完整引用对齐版本。

## 直接打回

- 同一主角资产被复制成多个角色却没有稳定ID。
- 平均站立人物填充来源中的遮挡、斧柄或模糊轮廓。
- 相机运动全部由人物横移冒充。
- 临时编号跨帧冲突。
- 导演假设未确认就写入Observed Facts。
- 未建立模型行为档案就把长提示词直接投入付费视频生成。
